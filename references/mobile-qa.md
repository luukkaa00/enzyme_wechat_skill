# 排版检查与公众号交付

## 生成两版及原图

使用`render_article.py`默认命令生成离线预览HTML、后缀为`_公众号.html`的公众号版和`_images`原图文件夹。预览保留三款SVG素材并内嵌图片；公众号版用简单的文字色底标题，引用导出原图。两版均保留内联样式、同一章节连续文字共框、遇图片断开；图片和图注在文本框外。

保存本次脚本报告中`image_files`列出的原图，不把历史残留文件当作本次配图。将公众号版与其同级配图文件夹一同保存交付；有多文件交付能力时保留相对目录关系，否则说明需将图片放入同名文件夹。用户未要求时不额外打包ZIP。独立原图按出现顺序编号；上传编辑器时按图注对应位置插入，不把本地路径当作公众号图片链接。用户只需预览时使用`--preview-only`。

两版使用同一份确认稿，不为了兼容编辑器改写正文或数据。核查标题、段落、小节、配图及图注顺序一致。公众号版不得出现SVG、外部CSS、远程字体或JavaScript。

## 手机宽度检查

使用环境现有的Node和Playwright运行：

```bash
node <skill目录>/scripts/check_mobile.mjs <预览HTML> <公众号HTML> --output-dir tmp/mobile-qa
```

脚本在375px和390px宽度下生成截图与`report.json`，检查横向溢出、图片是否加载、标题是否超出视口，并提示高度超过400px的段落。结果仅为排版风险线索，不能自动判断科学图片中字号是否可读。

- 结果为`automated_checks_passed`时，仍逐张查看截图：检查标题与装饰是否重叠，段落是否过长，图注是否对应；确认图中的坐标、单位、图例、对照无需放大即可辨认。
- 检查失败时，调整换行、段落或图像面板，重新检查两版。长段落只在保持文意及确认稿授权范围内拆分；若改写内容，按原有正文确认规则处理。
- 结果为`unverified`且原因为`browser_unavailable`时，继续检查HTML结构、图片字节与相对路径，说明尚未做实际视觉验证，不反复安装浏览器或用结构检查冒充视觉通过。
- 截图只作内部检查资料，除用户要求外不作为交付文件或保存到Library。

## 发布前交接

浏览器预览不代表公众号兼容性已经验证。将公众号版内容粘贴到编辑器，上传独立原图，检查后台预览中的标题、段落、图注与图片。没有明确授权时不登录账号或发布。
